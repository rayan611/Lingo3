# Audit — 2026-11-25 (app v0.7.26 → v0.7.27)

Whole-product check after Phases 0–2 and the design v2 work: tests, build, appearance, lag, display problems, code
conflicts and database health. **Facts only; what was not verified is listed at the end.**

## Method (repeatable)

1. `npm test` (444 checks), `npm run typecheck`, `npm run build`; bundle sizes from the build log.
2. Headless Chromium against a **mock build** (`VITE_SUPABASE_URL=https://fake.supabase.co npx vite build --outDir <dir>`
   served by a tiny static server that returns `index.html` for unknown paths, with the Supabase REST/RPC calls answered
   by Playwright routes): 9 routes × 4 widths (320, 390, 768, 1366) × en/fa × light/dark = **144 guest views**, plus
   **54 signed-in views** (student, teacher, admin; 320/390/1366; en/fa; `/academy`, `/academy/my`, `/academy/admin`)
   using a fake session in `localStorage`. Per view it measures: page horizontal overflow, elements wider than the
   viewport, console/page errors, error text on screen, tap targets under 36 px, text direction, time until the app
   mounted.
3. Static analysis of `academy.css` (hex colours, `!important`, breakpoints, repeated selectors) and a script that finds
   import cycles in `src/` (static imports only).
4. Supabase security and performance advisors for the Lingo3 project; Vercel deployment list and runtime-error summary.

## Database advisors (project `vfximbxcxczntqywdryd`)

No critical finding. Worth knowing, none changed in this pass:

- **Security (warn):** `hub_*` functions and `academy_open_classes` / `academy_teacher_calendar` are callable by `anon`.
  The `hub_*` ones are token-guarded control-center RPCs; the two Academy ones are intentionally public (free/busy
  calendar, open classes). 34 `SECURITY DEFINER` functions are callable by signed-in users — by design, each checks
  permission inside. `pg_trgm` lives in `public`. Four dictionary functions have a mutable `search_path`.
  **Leaked-password protection is off** — turn it on in Supabase Auth settings (owner action).
- **Security (info):** `academy_reviews`, `academy_review_reports`, `hub_access` have RLS and no policy (deny-all) —
  correct while reviews are disabled; reviews need policies before they are switched on.
- **Performance:** 31 foreign keys without covering indexes (mostly low-traffic Academy tables), 7 RLS policies that
  call `auth.uid()` per row instead of `(select auth.uid())`, 4 tables with several permissive SELECT policies, 22 unused
  indexes. Do these as one reviewed migration, not piecemeal.
